# Phase 0 技术研究与决策

## 1. RBAC 基座

**决策**：采用 RuoYi-Vue-Plus 6.x 作为系统管理基座，并新增独立 `ai-*` 模块。

**理由**：当前正式版使用 Java 21、Spring Boot 4.1、Sa-Token、MyBatis-Plus 和 Vue 3，已有
用户、角色、菜单、日志、限流和加密等能力；6.x 已移除旧多租户功能，符合单组织边界。

**替代方案**：5.x/Spring Boot 3 会承担更早的升级债务；从零实现 RBAC 重复建设；微服务版
对 MVP 过重。

## 2. 模块化策略

**决策**：Maven 多模块的模块化单体，通过公开应用服务、领域事件和 ArchUnit 限制依赖。

**理由**：在一个部署单元中保留事务简单性，同时让模型、Prompt、执行和工作流未来可拆分。

**替代方案**：初期微服务会引入网关、注册中心、消息一致性和部署成本；单业务模块边界模糊。

## 3. 数据存储

**决策**：PostgreSQL 17 是唯一权威业务数据库，动态结构使用 JSONB；Redis 仅用于缓存、限流
和短期协调。

**理由**：同时满足事务、约束、JSON 查询和未来 pgvector 扩展，减少 MVP 基础设施。

**替代方案**：MySQL 可用但未来动态查询和向量扩展需更多组件；MongoDB 增加事务复杂度。

## 4. 模型适配

**决策**：在 Spring AI 2.0 之上定义平台自己的 `ChatModelGateway`，首个适配器实现
OpenAI Compatible 协议。

**理由**：复用流式传输、消息和用量抽象，同时隔离业务与框架及供应商 SDK。

**替代方案**：业务直接使用 Spring AI 会扩大耦合；分别接厂商 SDK 会造成协议不一致。

## 5. 凭证保护

**决策**：供应商凭证使用应用级信封加密，主密钥由部署环境注入；外部调用凭证只保存摘要
和前缀，原值仅显示一次。

**理由**：供应商密钥需要运行时解密，而外部密钥只需要校验。

**替代方案**：数据库明文不可接受；外部密钥可逆加密没有必要。

## 6. 工作流执行

**决策**：MVP 自研受限 DAG 执行器；版本保存标准化 JSON；节点通过执行器注册表运行；任务
由受控线程池异步执行。

**理由**：仅需六类节点，无任意代码和复杂人工任务，更容易落实版本与节点追踪要求。

**替代方案**：Flowable/WarmFlow 面向审批；绑定现成 Graph 运行时会限制平台 DSL；消息队列
和独立 Worker 延后到容量证明有需要时。

## 7. 工作流画布

**决策**：Vue Flow 负责拖拽、缩放、连线和节点展示；服务端始终重新校验工作流。

**理由**：Vue 3 原生、可自定义节点，并与后端执行协议解耦。

**替代方案**：自行实现成本过高；审批流设计器与 AI 数据流交互不同。

## 8. 版本和并发控制

**决策**：主资源保存身份和指针，版本表保存不可变快照；草稿使用乐观锁；发布与回滚在事务
中更新发布指针并写审计事件。

**理由**：确保发布内容不被更新，并能安全处理并发修改和发布。

**替代方案**：主表覆盖无法可靠审计；只保存差异会提高读取和恢复复杂度。

## 9. API 与流式协议

**决策**：管理和非流式接口使用 JSON/HTTP；流式结果使用 SSE；契约采用 OpenAPI 3.1。

**理由**：浏览器和 Java 客户端易用，SSE 足以满足单向模型输出。

**替代方案**：WebSocket 对单向生成过重；gRPC 不利于浏览器和普通业务系统接入。

## 10. 测试与质量

**决策**：权限、模板、版本状态机、DAG 和凭证逻辑使用单元测试；数据库与接口使用
Testcontainers；核心旅程使用 Playwright；ArchUnit 防止跨模块越层访问。

**理由**：这些区域是数据泄露和发布事故的主要风险点，必须能够自动回归。

**替代方案**：只做接口手测无法稳定覆盖越权、并发和失败路径。
